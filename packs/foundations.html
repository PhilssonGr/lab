Token budget

One worked example of what a request costs, then what a month of those requests costs. The app, the traffic, and the token counts are illustrative assumptions. They are not measured usage and not a claim about a product that exists. The prices are EXAMPLE rates copied from one official pricing page.

The example app

A support-reply helper. One model request drafts a reply to one ticket. Assumptions used only for this arithmetic:

  • 2,000 uncached input tokens The new ticket. Billed at the input rate.
  • 8,000 cached input tokens A stable instructions prefix. This example assumes the provider bills these tokens at the cached-input rate.
  • 500 output tokens The draft reply. Billed at the output rate.
  • 20,000 requests in a month An illustrative traffic assumption, not an observed volume.

EXAMPLE prices

Model gpt-4.1. Standard prices, per 1,000,000 tokens, from the short-context columns. Input $2.00. Cached input $0.50. Output $8.00. Cache writes for gpt-4.1 are blank on that table, so this example adds no cache-write charge.

Source: OpenAI API pricing. Prices checked 2026-10-17, may change. Other models, the batch table, and long-context rates on the same page are different. This example does not use them. Amounts are US dollars, as on that page.

Per request

  • Uncached input $0.004
  • Cached input $0.004
  • Output $0.004
  • Uncached input2,000 × $2.00 ÷ 1,000,000 = $0.004
  • Cached input8,000 × $0.50 ÷ 1,000,000 = $0.004
  • Output500 × $8.00 ÷ 1,000,000 = $0.004
  • Per request$0.004 + $0.004 + $0.004 = $0.012

The three dollar amounts match only because these assumptions were chosen that way. A different token split would not land on three equal charges. The bar is a picture of this example, not a general rule.

The month, under the same assumptions

  • Uncached input20,000 × 2,000 = 40,000,000 tokens
    40,000,000 × $2.00 ÷ 1,000,000 = $80.00
  • Cached input20,000 × 8,000 = 160,000,000 tokens
    160,000,000 × $0.50 ÷ 1,000,000 = $80.00
  • Output20,000 × 500 = 10,000,000 tokens
    10,000,000 × $8.00 ÷ 1,000,000 = $80.00
  • Month$80.00 + $80.00 + $80.00 = $240.00
  • Check20,000 × $0.012 = $240.00

Left out of this example on purpose: retries, a second model call, images, tools, cache writes, and any higher rate past a size threshold. If the prefix is not actually billed as cached input, replace the $0.50 rate with the $2.00 input rate and run the same multiplication.

Pre-launch cost checklist

One pass before you ship a feature that calls a model. Each line is something you can do with a request you already send.

  1. List every model call one user action makes, including a retry and a second model if you have one.
  2. On one real request, write down uncached input tokens, cached input tokens, and output tokens as three numbers.
  3. Open the provider's current pricing page. Copy the input, cached-input, and output rates for the model you will ship, and write the date next to them.
  4. Multiply each token count by its own rate. Add the three results. That is the cost of one request.
  5. Write a monthly request count, and label it as an assumption until you have measured traffic.
  6. Multiply the per-request cost by that assumption. That is the monthly estimate.
  7. Check whether a longer prompt crosses a size threshold that uses a higher rate. If it does, price that request on the higher rate.
  8. Use the cached-input rate only after a real request shows those tokens billed as cached input.
  9. If the pricing page lists a cache-write charge, add it. Do not fold it into the cached-input rate.
  10. Choose a monthly number that should trigger an alert, and decide what the product does when that number is hit.
  11. Open the pricing page again on launch day. The EXAMPLE rates above were checked 2026-10-17 and may already differ.
